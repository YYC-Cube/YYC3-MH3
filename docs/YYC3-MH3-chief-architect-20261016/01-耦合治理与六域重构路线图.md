## 一、目标架构：六域垂直切片 × 端口-适配器

### 1.1 目录映射（迁移前 → 迁移后）

```
现状                                      目标
─────────────────────────────────────    ─────────────────────────────────────
src/types/index.ts                    →   src/kernel/contracts/   （域间共享契约：类型原子化分域）
src/config.ts                         →   src/kernel/config.ts    （叶层常量 + 路由映射）
src/domains/{batch,seed,pipeline,      →   src/domains/
             quality,ops}/                   ├── production/   ← ① 生产域
                                                   │  batch · seed · pipeline · quality · script · storyboard · asset
                                                 ├── editing/      ← ② 剪辑域（新建）
                                                   │  timeline · template · render
                                                 ├── admin/        ← ③ 管理域（新建）
                                                   │  project · board · cost · rbac · audit
                                                 ├── distribution/ ← ④ 推送域（上移 components/platform 语义）
                                                   │  channel · account · publish
                                                 ├── ai/           ← ⑤ AI 域
                                                   │  agent-cluster · react-c · assistant
                                                 └── platform/     ← ⑥ 基础设施域
                                                       queue · observability · storage
src/data/*.ts                         →   src/adapters/memory/fixtures/  （演示快照降级为适配器夹具）
src/adapters/{memory,local}/          →   src/adapters/{memory,local,indexeddb}/
src/components/platform/*             →   src/ui/distribution/  +  域名域钩子
src/views/*                           →   src/ui/routes/{view}/{container.tsx + 子组件 + hooks}
src/app/{composition,contexts,...}    →   src/app/{composition,providers,shell,usecases}/
```

### 1.2 分层矩阵（在现有 6 层基础上增加「域」维度）

现有矩阵（[boundary-guard](file:///Users/yanyu/YYC-Cube/YYC3-MH3/src/__tests__/boundary-guard.test.ts#L59-L69)）保留并**扩展一维**：在「层」约束之外，追加「同层跨域」约束。

| 层 | 允许引用内部层 | 新增：域级约束 |
| --- | --- | --- |
| `kernel` | —（叶） | 全域共享，无域标签 |
| `domains/<域>` | `kernel` + **本域** | **禁止引用其他 `domains/<其他域>`**（同层跨域=违规） |
| `adapters/<实现>` | `kernel` + `domains`（端口） + `adapters/memory/fixtures` | 一个适配器可跨域实现端口，但**只依赖端口接口** |
| `ui/components` | `kernel` + `domains`（仅端口/hook） | 按域子目录，**禁跨域 UI 互引**（除 `ui/common`） |
| `ui/routes` | 上述 + `ui/components` | 页面容器只编排本域 |
| `app` | 全部 + `adapters` + `ui/routes` | 组合根唯一 DI 点 |

### 1.3 跨域访问规范（三条铁律）

1. **禁止直接 import**：`domains/A/**` 不得 `import` `domains/B/**`。
2. **跨域协作走两种通道之一**：
   - **同步契约**：`kernel/contracts/<域>.ts` 暴露的只读类型/DTO（编译期约束）；
   - **异步事件**：`domains/platform/queue` 的领域事件端口（运行期解耦，见 ⑥ 基础设施域）。
3. **应用层编排**：真正的跨域流程（如「生成完成 → 质检 → 归因 → 写回」）收敛到 `app/usecases/`，域只出规则、不出流程。

> 违禁示例：`domains/editing/timeline.ts` 直接 `import { findCurrentBatch } from "../production/batch"` → **违规**。
> 合法示例：`app/usecases/renderTimeline.ts` 组合 `production` 与 `editing` 两个域的纯函数；或经 `kernel/contracts` 的 `BatchRef` 类型传递。
