# 🏷️ 标头/标尾合规化专项总结日志

## 一、任务目标

依据 `docs/YYC3-团队通用-标准规范` 团队规范，对全局代码与文档统一注入合规标头/标尾，建立可追溯迭代机制（updated 刷新 + SemVer 递增 + 变更历史），并以幂等脚本保证重复执行零副作用。

## 二、规范依据

| 规范条款 | 要求 | 落地方式 |
| -------- | ---- | -------- |
| 开发标准 1.1/1.3 | MD YAML Front Matter 十字段 | stampMd 全量补齐（file/description/author/version/created/updated/status/tags/category/language） |
| 开发标准 1.9 | 追溯机制：updated + 版本递增 + 变更历史表 | 结构变更时 PATCH+1，并注入变更历史表 |
| 开发标准 2.4-2.7 | TS/CSS/HTML/配置/测试 JSDoc 标头 | stampCode 按语言分流模板（`/**` / `<!-- -->` / `#`） |
| 文档闭环 | 品牌铭牌（FM 后五条引言）+ `<div align="center">` 版权标尾 | MD 结构化注入 |

## 三、执行过程（三阶段闭环）

### 阶段 1：首轮批量执行（stamper v1.0.0）

- 扫描 **124** 个文件（md 72 / ts·tsx·css 52 / html 1 / py 1 / yaml 1），错误 0
- 注入统计：MD 新建 FM 35 / MD 更新 FM 37 / 品牌铭牌 40 / 变更历史 40 / 代码标头 52 / 标尾 94

### 阶段 2：幂等复验暴露缺陷（二次运行取证）

| # | 缺陷 | 根因定位 | 受影响面 |
| - | ---- | -------- | -------- |
| 1 | MD 版本号二次递增（24 文件 `.2` 漂移） | `stampMd` 品牌路径误用 `fmMatch[1]`（原始 FM）覆盖已更新的 `fm` 变量；且每次执行无条件 PATCH+1 | 72 个 MD |
| 2 | html/py/yaml 重复注入（4 文件双标头） | 标头检测仅匹配 `/*` + `file:`，`<!-- -->` 与 `#` 注释形态漏检 | index.html / 引擎模版.py / template_config.yaml / pnpm-lock.yaml |
| 3 | 生成物被误标 | 未跳过 pnpm-lock.yaml | 1 文件 |
| 4 | 标头描述取到类型契约 | 导出符号正则 `interface|type` 与 `function|const` 同组优先匹配先出现者（如 `ButtonProps`） | 30 个 tsx |

### 阶段 3：修复 + stamper v1.1.0 升级 + 幂等复验

**修复脚本**（`attachments/yyc3-compliance-repair.mjs`）：

- A. pnpm-lock.yaml 还原：循环剥离双标头 + 剥离标尾（生成物不标注）
- B. 三文件注释块去重（保留首组标头/标尾）；index.html 标尾残留 © 重复块手动收敛为「品牌铭牌 + ©」标准结构
- C. 40 个 MD FM 规范化：updated 统一 2026-10-11、必填字段补齐、合规化变更行版本与 FM 对齐

**stamper v1.1.0**（`attachments/yyc3-header-stamper.mjs`）：

1. 品牌路径改用已更新的 `fm` 变量（修复缺陷 1 的回退丢失）
2. 无结构变更（铭牌/历史/标尾齐备）时跳过 FM 重写与版本递增（根治二次递增）
3. 标头检测按语言分流：html `/<!--/ + /file:\s/`、py·yaml `/^# file:\s/m`（修复重复注入）
4. walk 跳过 `pnpm-lock.yaml`（生成物豁免）
5. `codeFacts` 优先 `function|const|class|enum`，回退 `interface|type`

**描述符号批量校正**：30 个 tsx（13 视图 + 15 组件 + Button）`— XxxProps` → `— Xxx`，全部经导出存在性校验。

## 六、经验沉淀与建议

1. **批量修改必须先幂等验证**：首轮执行后立即二次运行取证，全部缺陷均由复验暴露——"写完即验幂等"应成为批处理脚本的标准动作。
2. **检测先于注入**：幂等的关键在检测正则与注入模板严格同构，多语言注释形态需逐一覆盖。
3. **版本递增绑定结构变更**：元数据刷新不应触发 SemVer 递增，避免版本噪声。
4. **建议**：后续可将会话目录 attachments 下两脚本纳入 `package.json` scripts（如 `compliance:check`），供 CI 门禁复用。
